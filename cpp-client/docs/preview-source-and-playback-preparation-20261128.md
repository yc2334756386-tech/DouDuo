# 0.20.21：预览来源交接、首次处理配置和相邻预热

## 预览

用户截图显示退场图片与原位图片同时可见。当前来源可见时创建的阅读快照、全页模糊快照都包含该媒体，原生 Zoom 只管理真实来源，无法一并隐藏快照里的副本。

现在建立同位置、同尺寸的独立过渡 UIImageView，原来源仅暂时设为透明，不改变布局。过渡图和原来源均不显示时再截取两层背景；之后让原生 Zoom 使用过渡图。退场完成后在同一事务恢复原来源透明度、移除过渡图和阅读快照。保留原 Zoom、模糊缩放参数、阅读锚点和延后分页，不更换动画时长/曲线。

## 可选音视频处理

旧路径先将 item 交给播放器，随后异步回调才设置 audioMix / videoComposition。这会在已开始播放或已完成 preroll 的来源上再次配置处理，既不能保证预热结果有效，也可能改变音频开始时的状态；没有同版本设备错误日志，尚不能证明其解释所有无声和卡顿。

新 item 先准备可选处理，再绑定到播放器。相邻项在后台准备；完成或 650ms 兜底时绑定一次。用户切到仍未准备完的来源时立即封存当时可用的配置，直接开始原声/原画，不让增强成为播放等待条件。晚到的自动配置只能结束，不能再改动该 item。主动更换画面预设仍可显式应用；调音参数通过已有 C++ 原子控制实时更新，首次开启则对后续新作品生效，并清理尚未使用的旧预热项。

图文和收藏音乐的音频同样在首次绑定前准备，150ms 后仍未就绪时使用原声。异步完成检查当前播放器、暂停和离开意图，播放结束通知绑定到明确的 item，避免尚未赋值 currentItem 时监听全部来源。

实时音频回调不再创建日志字符串，只保存原子取源失败/异常空读计数。播放中连续失败或异常空读达到阈值时，主线程单次移除该项音频增强以恢复原声，保留播放器、当前视频进度与播放意图。此恢复不是自动反复暂停或重新 seek。

## 预热

开始手势时暂停新 preroll，保留已进行的有限预热直到完成，避免刚要使用下一条就取消。预热完成后通知可见相邻单元格挂接已准备的首帧；前台池仍限制为三个。后台、回收和作废仍取消，未使用 asset 的加载也随回收取消。

新增 `playback.pipeline.bound`、`audio.tap.attached`、`audio.tap.bypass`、`audio.tap.recovered_original` 等状态日志，不记录会话或媒体地址。按用户要求只检查源码、云端编译和包体，未执行自动化或真机测试。实际切片性能、退场视觉及音频恢复仍需设备确认。
