# RIFE 4.25 在 Core ML 和 Apple Neural Engine 上的可行性

2026-11-28。RIFE 4.25 有明确的 Core ML 转换路线。能否用 ANE 稳定满足 DouGlass 的实时插帧时限，取决于动态采样的设备分配、半精度误差和视频帧转换开销。本次核对了上游权重、推理源码和 Apple 转换器，已用固定 320×192 的 FP16 输入生成 MIL 图。真机性能仍待验证。

## 版本和权重

- Practical-RIFE 的 4.25 于 2024-09-19 发布。上游明确把模型表中链接的内容也纳入 MIT 许可。分发转换后的模型时，应附带 `Copyright (c) 2021 hzwer` 和完整 MIT 许可文本。实测官方 `RIFEv4.25_0919.zip` 的 SHA-256 为 `e63d481b7ae5d4a4e6ad7ac5b410ff78f3bf7be3b51b2e38ca8152747abde5b4`，其中包含配套的 `train_log/IFNet_HDv3.py`、`RIFE_HDv3.py` 和 `flownet.pkl`。 [上游版本表](https://github.com/hzwer/Practical-RIFE/blob/bbfd2ea90910789a860ea3e2b32a240cd577b75e/README.md#trained-model) · [上游许可证](https://github.com/hzwer/Practical-RIFE/blob/bbfd2ea90910789a860ea3e2b32a240cd577b75e/LICENSE) · [4.25 原始发行包](https://drive.google.com/file/d/1ZKjcbmt1hypiFprJPIKW0Tt0lr_2i7bg/view)
- `mlx-community/RIFE-4.25` 的 `model.safetensors` 是同一 `flownet.pkl` 转换成的 FP32 权重，固定版本 `6b650eaa5664aab280119511fe944861491aa15e`，大小 22,674,262 字节，SHA-256 `40bd5bdc9b41d22ad2fad79da325dcd68988a90d8b8e8fb7b67ed5eedebccf5f`。若选用该权重，按 MLX 转换脚本逆向还原键名和维度。普通卷积、`beta` 用 `(0,3,1,2)`，`encode.cnn3.weight` 和每个 `blockN.lastconv.weight` 用 `(3,0,1,2)`，偏置直读。还原 `conv0.N.conv` 为 `conv0.N.0`、`lastconv` 为 `lastconv.0` 后，严格核对推理层的键名及形状。 [权重文件及校验值](https://huggingface.co/mlx-community/RIFE-4.25/blob/6b650eaa5664aab280119511fe944861491aa15e/model.safetensors) · [MLX 权重转换脚本](https://github.com/xocialize/rife-mlx/blob/764b89be56497fb26243d1de75f2957f3889e5d3/rife_mlx/utils/convert.py)

## Core ML 转换和运行验证

1. 以官方 PyTorch 4.25 推理图作为参考，追踪固定 `NCHW` 尺寸的两帧 RGB 输入，固定插值位置 `0.5`，只输出合成帧。首个模型用 `scale=1`，像官方推理包装器一样显式传入五个尺度 `[16, 8, 4, 2, 1]`，宽高按 64 补零并在输出裁掉。可先尝试 360×640 竖屏画面，模型内部用 384×640，并报告缩小推理尺寸的画质影响。 [4.25 原始发行包](https://drive.google.com/file/d/1ZKjcbmt1hypiFprJPIKW0Tt0lr_2i7bg/view) · [MLX 推理包装器](https://github.com/xocialize/rife-mlx/blob/764b89be56497fb26243d1de75f2957f3889e5d3/rife_mlx/model/RIFE_HDv3.py)
2. 用 `coremltools 9.0` 导出 iOS 18 的 `mlprogram`，先保留全 FP32 作数值对照，再尝试 FP16 版。五个 IFBlock 逐级累加光流，反复用动态坐标扭曲 RGB 和特征图。Apple 的 PyTorch 前端会将 `grid_sampler` 转为 `resample`，保留双线性、`border`、`align_corners=True`。IFBlock 内部的缩放用 `align_corners=False`，也有对应转换。另有 `pixel_shuffle` 转换。应以实际导出结果确认整图可转换。 [上游扭曲函数](https://github.com/hzwer/Practical-RIFE/blob/bbfd2ea90910789a860ea3e2b32a240cd577b75e/model/warplayer.py#L13-L28) · [转换器采样实现](https://github.com/apple/coremltools/blob/9.0/coremltools/converters/mil/frontend/torch/ops.py#L444-L474) · [Core ML 精度规则](https://apple.github.io/coremltools/docs-guides/source/typed-execution.html)
3. Apple 明确说明全 FP32 ML Program 无法使用 ANE。FP16 版用 `cpuAndNeuralEngine` 加载时仍允许 CPU 回退。在目标设备上，通过 `MLComputePlan` 核对卷积、`resample`、缩放及像素重排的首选设备和估算成本，再用 Instruments 确认实际执行时间。若采样落在 CPU 且频繁跨设备，先测 `.all` 的调度结果。另一种可验证的方案是让 ANE 跑卷积子图，Metal 承担双线性扭曲，并把光流累加和坐标保留为 FP32。其实际收益须计入多个子图调用和数据交换开销。 [Core ML 计算单元](https://developer.apple.com/documentation/coreml/mlcomputeunits/cpuandneuralengine) · [计算计划](https://developer.apple.com/documentation/coreml/mlcomputeplan-1w21n) · [Apple 性能分析示例](https://developer.apple.com/videos/play/wwdc2024/10161/)
4. DouGlass 当前从 `AVPlayerItemVideoOutput` 取双平面 YCbCr 帧。可用 Metal 将其转换为 RGB 模型输入，保留颜色矩阵和范围，使用复用的 pixel buffer，并复用现有异步调度。Core ML 的 `ImageType` 可直接收发 `CVPixelBuffer`，可比较其成本和 `MLMultiArray` 路径。只在下一帧展示截止时间前交付合成帧，模型来不及处理时继续播放原帧。对比 FP32、FP16 和系统 VideoToolbox 插帧时，计入缩放、颜色转换、推理以及展示排队，测量 p95 和掉帧率，并覆盖快速运动、字幕、切镜和持续播放。 [DouGlass 视频调度](../DGVideoEffects.mm) · [Core ML 图片输入输出](https://apple.github.io/coremltools/docs-guides/source/image-inputs.html)

MLX 项目报告的 1080p 插帧为 M5 Max GPU FP32 平均 554 ms，单次推理峰值内存 1,931 MB。其 FP32 最大绝对误差 `0.00143` 来自一组随机的 64×64 输入，作者报告 FP16 误差上升到 `0.031`。这些数字描述该 MLX 实现，可用于确定需要测的指标。DouGlass 的设备延迟、误差和芯片分配仍需由 Core ML 产物确定。 [MLX 性能报告](https://github.com/xocialize/rife-mlx/blob/764b89be56497fb26243d1de75f2957f3889e5d3/docs/REPORT.md) · [MLX 精度报告](https://github.com/xocialize/rife-mlx/blob/764b89be56497fb26243d1de75f2957f3889e5d3/README.md#parity) · [PyTorch 对照数据生成脚本](https://github.com/xocialize/rife-mlx/blob/764b89be56497fb26243d1de75f2957f3889e5d3/scripts/gen_goldens.py#L55-L70)
