# 0.20.19：翻页回退、预加载与实验室布局

## 源码证据

- `Interface.mm` 在 0.20.18 拦截系统分页的目标偏移，取消系统惯性并用额外的属性动画完成吸附。连续滑动需要处理第二套动画状态。
- 原相邻预加载同时等待全局动画预算与当前作品首帧；列表分页也位于该首帧判断之后，当前来源慢时下一条及列表补充一起延后。
- 播放器池按作品与当前来源地址组成键。磁盘下载完成使来源由远程切成本地文件时，已解码的远程播放器不再命中原精确键。
- 实验室分段控件、滑块使用表宽及 autoresizing，标题仍由系统 subtitle 单元格居中排版，无法约束实际内容区。

## 实现

- 视频翻页、自动上滑、评论展开/收起/拖动恢复 `71d52b5` 的实现。三列作品的原生 Zoom 保留。
- 停稳约 60ms 后准备相邻来源和请求补充分页，不要求当前首帧或无关动画先完成。手指翻页期间仍停止新增准备，磁盘整片下载等待当前画面就绪。
- 本地文件出现后仍可复用相同作品已就绪的流式播放器；池上限继续为 3，不新增常驻播放器。失败来源不能复用。
- MetalFX 的 GPU 设备、上下文与管线在非动画的实际处理帧上延迟创建，避免在相邻播放器构造时创建多套资源。
- 实验室使用 contentView 的 layoutMarginsGuide 约束纵向 stack，标题、说明与控件分行，行高自动适应。
- 评论图片预览使用临时阅读界面快照作为模糊背景，同步做轻微缩放；不缩放真实评论列表，不改动原评论锚点和延后分页发布策略。图片来源缩放仍由 UIKit Zoom 完成。
- 新日志：`feed.preload`、`playback.prepare`、`cache.idle`。只记录状态、计数、来源类别，不记录媒体地址或登录资料。

## 验证边界

按用户要求仅检查源码、云端编译和 IPA 包体，不执行自动化或设备测试。上述等待路径由源码确认，但并未用设备性能采样证明它们解释全部卡顿。尚不能保证任意网络、源地址或设备状态下的零等待播放；最多 50 条是待播缓存队列上限，实际落盘仍受网络与磁盘限制。
