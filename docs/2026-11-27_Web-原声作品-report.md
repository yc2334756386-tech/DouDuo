## 后续：列表资料与起播（0.20.0，2026-11-28）

继续使用公开原声 `7149936801028131598` 做只读端点核对：把 `count` 从 15 扩大为 50 或 100，返回 17 条；返回游标为 20。请求游标 0、1、15、20、30、40、60、100、1000 均返回相同批次。不能把增加请求数量等同于已经解锁完整列表，也不能靠递增本地游标制造分页。

移动列表中有视频地址、作品 ID 与统计数据，但缺少逐条作者和原声对象。客户端现在标记这些简略记录，按可见作品请求平台作品详情，使用相同作品 ID 的真实详情补全作者头像与昵称；合并重复请求，同时最多两条，缓存按账号隔离。当前作品请求优先，详情不可用时不捏造作者。

移动分页不前进时尝试现有官网桌面签名请求。桌面接口仍可能返回空内容，这种情况下保留已取得的条目并显示平台分页限制。没有证据证明该路径在用户已登录设备上可取得完整原声作品。

对于列表中的作品 `7194349373684223269`，公开移动结果同时提供 CDN 直连和 `/aweme/v1/play/` 重定向。一次 1024 字节 Range 只读比较中，直连 HTTP 206 约 286 ms，重定向 HTTP 206 约 807 ms。这只证明该次请求存在重定向成本，不是 iPhone 首帧性能测量。原片源选择代码全局优先重定向，现改为当前清晰度直连优先，并保留失败备用。

客户端不会等待磁盘缓存下载完成才交给播放器：已完成的本地文件可直接播放，否则 AVPlayer 使用远程 URL。新版本降低起播前向缓冲目标、明确不扫描精确时长，当前画面出现前不新增相邻预缓冲，出画后仅向前新建一条。补全资料不会重建健康的播放器。诊断记录资源就绪、片源类别与首帧缓冲，方便后续从实际设备日志分辨网络、解码与页面开销。

上述是源码修改和只读请求观察。遵从用户要求，不运行自动化或设备测试；云编译与 IPA 结构检查不能证明实际设备已达到滑到即播。
